Page Object Model in Selenium Java: The Complete Guide

By Automation AI Lab · June 2025 · ⏱ 10 min read

The Page Object Model (POM) is the single most important design pattern in Selenium test automation. It makes your tests readable, maintainable, and scalable.

Why POM Exists

Without POM, when a UI element changes, you hunt through every test that touches it. With POM, you update it in one place and every test is automatically fixed.

Project Structure

src/
├── main/java/pages/
│   ├── LoginPage.java
│   ├── DashboardPage.java
│   └── BasePage.java
└── test/java/tests/
    ├── LoginTest.java
    └── DashboardTest.java

Step 1 — Create a Page Class

package pages;
import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;

public class LoginPage {
    private WebDriver driver;
    private By usernameField = By.id("username");
    private By passwordField = By.id("password");
    private By loginButton   = By.cssSelector("button[type='submit']");

    public LoginPage(WebDriver driver) { this.driver = driver; }

    public void enterUsername(String u) { driver.findElement(usernameField).sendKeys(u); }
    public void enterPassword(String p) { driver.findElement(passwordField).sendKeys(p); }
    public void clickLogin()            { driver.findElement(loginButton).click(); }

    public DashboardPage loginAs(String u, String p) {
        enterUsername(u); enterPassword(p); clickLogin();
        return new DashboardPage(driver);
    }
}

Step 2 — Use Page Objects in Tests

public class LoginTest {
    WebDriver driver;
    LoginPage loginPage;

    @BeforeMethod public void setUp() {
        driver = new ChromeDriver();
        driver.get("https://example.com/login");
        loginPage = new LoginPage(driver);
    }

    @Test public void validLoginRedirectsToDashboard() {
        DashboardPage dashboard = loginPage.loginAs("user@test.com", "pass");
        Assert.assertTrue(dashboard.isLoaded());
    }

    @AfterMethod public void tearDown() { driver.quit(); }
}
Best practice: Page methods return void or another page object. Never put assertions inside page classes.

POM Best Practices

  • One page class per page or major component
  • Keep locators private — never expose them to tests
  • Use meaningful method names: clickAddToCart() not clickButton()
  • Create a BasePage for shared waits and utilities
  • Return page objects from methods that navigate to a new page
