Page Object Model in Selenium Java: The Complete Guide

By SeleniumLab · June 2025 · ⏱ 10 min read

The Page Object Model (POM) is the single most important design pattern in Selenium test automation. It makes your tests readable, maintainable, and scalable. Here's how to implement it correctly in Java.

Why POM Exists

Without POM, when a UI element changes (say, a button ID gets renamed), you have to hunt through every test that touches that button and update each one. With POM, you update it in one place — the page class — and every test that uses it is automatically fixed.

Project Structure

src/
├── main/java/
│   └── pages/
│       ├── LoginPage.java       ← page class
│       ├── DashboardPage.java
│       └── BasePage.java        ← shared utilities
└── test/java/
    └── tests/
        ├── LoginTest.java       ← test class (uses page objects)
        └── DashboardTest.java

Step 1 — Create a Page Class

Each page gets its own class. The class holds locators and actions for that page only.

package pages;

import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;

public class LoginPage {

    private WebDriver driver;

    // Locators — defined once
    private By usernameField = By.id("username");
    private By passwordField = By.id("password");
    private By loginButton   = By.cssSelector("button[type='submit']");
    private By errorMessage  = By.className("error-msg");

    public LoginPage(WebDriver driver) {
        this.driver = driver;
    }

    // Actions — readable methods
    public void enterUsername(String username) {
        driver.findElement(usernameField).sendKeys(username);
    }

    public void enterPassword(String password) {
        driver.findElement(passwordField).sendKeys(password);
    }

    public void clickLogin() {
        driver.findElement(loginButton).click();
    }

    public String getErrorMessage() {
        return driver.findElement(errorMessage).getText();
    }

    // Fluent login — combines steps
    public DashboardPage loginAs(String username, String password) {
        enterUsername(username);
        enterPassword(password);
        clickLogin();
        return new DashboardPage(driver);
    }
}

Step 2 — Use Page Objects in Tests

Tests become readable English — no locators visible at all:

package tests;

import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;
import org.testng.Assert;
import org.testng.annotations.*;
import pages.LoginPage;
import pages.DashboardPage;

public class LoginTest {

    WebDriver driver;
    LoginPage loginPage;

    @BeforeMethod
    public void setUp() {
        driver = new ChromeDriver();
        driver.get("https://example.com/login");
        loginPage = new LoginPage(driver);
    }

    @Test
    public void validLoginRedirectsToDashboard() {
        DashboardPage dashboard = loginPage.loginAs("user@test.com", "password123");
        Assert.assertTrue(dashboard.isLoaded(), "Dashboard should be visible after login");
    }

    @Test
    public void invalidLoginShowsError() {
        loginPage.enterUsername("wrong@user.com");
        loginPage.enterPassword("wrongpassword");
        loginPage.clickLogin();
        Assert.assertEquals(loginPage.getErrorMessage(), "Invalid credentials");
    }

    @AfterMethod
    public void tearDown() {
        driver.quit();
    }
}
Best practice: Page methods should return either void or another page object. Never put assertions inside page classes — assertions belong in the test.

PageFactory Alternative

Selenium's PageFactory lets you declare locators as annotations:

import org.openqa.selenium.WebElement;
import org.openqa.selenium.support.FindBy;
import org.openqa.selenium.support.PageFactory;

public class LoginPage {

    @FindBy(id = "username")
    private WebElement usernameField;

    @FindBy(id = "password")
    private WebElement passwordField;

    @FindBy(css = "button[type='submit']")
    private WebElement loginButton;

    public LoginPage(WebDriver driver) {
        PageFactory.initElements(driver, this);
    }

    public void enterUsername(String text) { usernameField.sendKeys(text); }
    public void enterPassword(String text) { passwordField.sendKeys(text); }
    public void clickLogin() { loginButton.click(); }
}

POM Best Practices

  • One page class per page (or per major component)
  • Keep locators private — never expose them to tests
  • Use meaningful method names: clickAddToCart() not clickButton()
  • Create a BasePage for shared waits and utilities
  • Return page objects from methods that navigate to a new page
