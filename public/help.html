Section 1

🚀 Getting Started

Two ways to run the app — pick the one that fits your setup.

A

Online / Cloud Mode No install

Visit the live URL and use a Groq API key (free at console.groq.com). Set your key in the Settings panel or as an environment variable. The AI will answer using Groq's cloud models — no local setup needed.

B

Local Mode Fully offline

Clone the repo, run npm install && node server.js, then open http://localhost:3000. Install Ollama for local AI models. No internet required after setup.

git clone https://github.com/saifafzal1/selenium-java-training
cd selenium-training
npm install
node server.js
# Open http://localhost:3000
💡

Recommended for beginners: Start with Online Mode (Groq) to avoid setup friction. Switch to Local Mode later when you want to build your project with AI-generated code saved directly to your machine.

🎓 Explain Mode — Step-by-Step Examples

Best for: understanding a new concept, getting a plain-English definition, seeing how something works with analogies.

1

Activate Explain Mode

Open the chat panel → Skills tab → click 🎓 Explain. A welcome message appears with suggested prompts.

2

Ask about any concept

Type naturally — no special syntax needed. Examples:

"Explain WebDriver implicit vs explicit waits with examples"
"What is Page Object Model and why should I use it?"
"Walk me through how XPath locators work"
"Explain TestNG annotations — @Test, @BeforeMethod, @AfterMethod"
3

Read the explanation + code

The AI responds with a numbered explanation, a real-world analogy, and a short runnable Java code block. For example, asking about waits returns something like:

// ❌ Implicit wait — applies globally, fragile
driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(10));

// ✅ Explicit wait — waits for a specific condition
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
WebElement btn = wait.until(
    ExpectedConditions.elementToBeClickable(By.id("submit"))
);
btn.click();
4

Follow up or go deeper

Ask follow-up questions in the same chat — the AI remembers context. Try: "Can you show me a more complex example?" or "What happens if the element never appears?"

⚙️ Generate Mode — Step-by-Step Examples

Best for: creating new Java files, scaffolding framework components, writing POM classes and TestNG tests.

1

Activate Generate Mode

Skills tab → click ⚙️ Generate. The AI now acts as a senior automation engineer focused on production-quality code.

2

Describe what you want to build

Be specific — mention the page, actions, and pattern you want:

"Generate a LoginPage class using Page Object Model.
The page at https://example.com/login has:
- Username field (id: 'username')
- Password field (id: 'password')
- Submit button (id: 'login-btn')
- Error message (class: 'error-msg')"
3

Get a complete, ready-to-use Java file

Generate Mode returns a full class — proper package declaration, imports, WebDriverWait, and all methods:

package com.selenium.pages;

import org.openqa.selenium.*;
import org.openqa.selenium.support.*;
import org.openqa.selenium.support.ui.*;

public class LoginPage {
    private WebDriver driver;
    private WebDriverWait wait;

    @FindBy(id = "username")    private WebElement usernameField;
    @FindBy(id = "password")    private WebElement passwordField;
    @FindBy(id = "login-btn")   private WebElement loginButton;
    @FindBy(css = ".error-msg") private WebElement errorMessage;

    public LoginPage(WebDriver driver) {
        this.driver = driver;
        this.wait   = new WebDriverWait(driver, Duration.ofSeconds(10));
        PageFactory.initElements(driver, this);
    }

    public void login(String username, String password) {
        wait.until(ExpectedConditions.visibilityOf(usernameField));
        usernameField.clear();
        usernameField.sendKeys(username);
        passwordField.sendKeys(password);
        loginButton.click();
    }

    public String getErrorMessage() {
        wait.until(ExpectedConditions.visibilityOf(errorMessage));
        return errorMessage.getText();
    }
}
4

Save to your project folder

Click 💾 Save to Project below the code block. The file is written directly to your Maven project's src/test/java folder. Click the toast to open it in VS Code instantly.

5

More things you can generate

  • "Generate a DriverFactory with Chrome and Firefox support"
  • "Write a BasePage class with common wait utilities"
  • "Create a TestNG data provider test for the login page"
  • "Generate a testng.xml suite for parallel execution"
  • "Write a ConfigReader to read config.properties"

Section 4

💻 VSCode Integration Workflow

The recommended way to build your automation framework — AI generates code in the browser, you run and iterate in VS Code.

⚠️

Requires local mode. VSCode file integration only works when the app is running via node server.js on localhost — not on the hosted Vercel URL.

Step-by-step workflow

1

Create your Maven project in VS Code

Open VS Code's terminal and scaffold a Maven project:

mvn archetype:generate \
  -DgroupId=com.selenium.training \
  -DartifactId=my-selenium-framework \
  -DarchetypeArtifactId=maven-archetype-quickstart \
  -DinteractiveMode=false

cd my-selenium-framework
code .   # opens in VS Code
2

Set the Project Folder in Automation AI Lab

Click ⚙️ (Settings gear) in the bottom-left of the app. Under Project Folder, paste the path to your Java sources:

/Users/yourname/my-selenium-framework/src/test/java

Click Save Path then Test Connection — you should see a green confirmation.

3

Ask the AI to generate code

In the chat panel, ask for a Java file — for example:

"Generate a LoginPage class using Page Object Model
for a login form at https://example.com/login"

The AI responds with a complete Java class. A 💾 Save to Project button appears below the code block.

4

Save → VS Code opens the file

Click Save. The file is written to your project folder. A toast notification appears — click it to jump directly to the file in VS Code (uses the vscode://file/ URL scheme).

💡

Enable Open in VS Code in Settings to make the toast clickable. Requires VS Code installed with the default URL handler.

5

Run & debug in VS Code

Back in VS Code, run your test with:

mvn test -Dtest=LoginTest

If you see errors, copy the stack trace and paste it back into the Automation AI Lab chat: "Fix this error:" — the AI will diagnose and provide corrected code.

6

Push to GitHub after each module

Commit your working code after each module. This builds your portfolio and is required for the AI code review at the end.

git add .
git commit -m "Module 3: Page Object Model complete"
git push origin main

Section 5

📚 Local RAG — Offline AI with Real Docs

RAG (Retrieval-Augmented Generation) syncs real Selenium documentation to your machine so the AI gives accurate answers even when fully offline.

🔒

Fully Private

Your questions and documentation never leave your machine. Everything runs through Ollama locally.

✈️

Works Offline

Sync once when you have internet. After that, the AI answers from local embeddings — no connection needed.

🎯

More Accurate

Answers grounded in real Selenium, TestNG, and Java docs — not just model training data.

Setup (one-time)

1

Install Ollama

Download from ollama.com and run:

ollama serve
2

Pull the embedding model

ollama pull nomic-embed-text:latest

This is a 274MB model used to convert text into vectors. It's not a chat model — it runs silently in the background.

3

Pull a chat model

ollama pull qwen2.5-coder:14b    # best for code (8GB)
# or
ollama pull llama3.2:3b           # lighter option (2GB)
4

Sync documentation

Open ⚙️ Settings → click 📥 Sync Docs. A progress bar shows each of the 7 documentation sources being fetched and embedded:

  • Selenium WebDriver API
  • Element interactions & locators
  • Explicit & implicit waits
  • User interactions (Actions API)
  • Best practices guide
  • TestNG documentation
  • Selenium Grid

The RAG badge turns ● Synced when done.

💡

How it works: Every message you send to a local Ollama model is first converted to a vector. The app finds the 3 most relevant documentation chunks (cosine similarity), and injects them into the AI's context window. The AI then answers using real docs — not just memorized training data.

Section 7

⚡ Smart Mode

Smart Mode chains two AI models — a fast model refines your question first, then the selected model gives a better answer.

Smart Mode OFF

Your message → AI model → answer.

Fast, direct. Good for simple questions.

Smart Mode ON ⚡

Your message → Qwen refines → selected model answers with improved context.

Slower (one extra call) but noticeably better for complex coding tasks.

Enable in ⚙️ Settings → Smart Mode toggle. Best used when generating full framework files or debugging complex issues.

❓ Frequently Asked Questions

Q

I don't have a Groq API key. Can I still use the AI?

Yes — install Ollama locally and use a free local model like qwen2.5:7b or llama3.2:3b. No API key needed. Groq also offers a free tier at console.groq.com.

Q

My progress disappeared. How do I restore it?

Progress is saved in your browser's localStorage. If you cleared browser data, it will reset. When running in local mode (node server.js), progress is also saved to data/progress.json on disk — this persists across browser clears.

Q

The Save to Project button isn't working.

This requires local mode (node server.js). Make sure you've set a valid project folder path in Settings → Project Folder, and clicked Test Connection to confirm the path exists.

Q

RAG sync fails with "Cannot reach Ollama".

Make sure Ollama is running: ollama serve. Also ensure you've pulled the embedding model: ollama pull nomic-embed-text:latest. The RAG sync connects to localhost:11434.

Q

How many lessons are there and how long does it take?

30 lessons across 6 modules, approximately 8–12 hours total depending on how much time you spend on exercises. You can pause and resume at any time — progress is saved automatically.

Q

Can I use IntelliJ IDEA instead of VS Code?

Yes — the Save to Project feature writes files to any folder you specify. The "Open in VS Code" one-click feature uses VS Code's URL scheme, so that part is VS Code only. For IntelliJ, simply point the project folder to your IntelliJ project's src/test/java directory and open the saved files manually.

Q

Is my code sent to the cloud when I use local Ollama models?

No. When using Ollama, all processing happens entirely on your machine. Nothing is sent externally. Only Groq and Anthropic models send data to their respective cloud APIs.
